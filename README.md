# factors_framework

Cross-sectional factor research on U.S. equities. Each paper has a separate replication project; all projects share data and the `factorlab` framework.

## Directory structure

```
framework/ unified framework factorlab (all projects call it)
  factorlab/ backtesting engine, cross-sectional processing, factor construction, evaluation, data reading and writing, standard reports
  tests/ framework tests
pipeline/ processes the original files of data/source into data/base (shared by all projects)
factors/replication project, one folder for each paper
  <Author_Year_Topic>/
    doc/                         paper PDF (excluded from Git) and notes.md (definitions, deviations, open tasks)
    build.py reads data/base → build factor exposure → writes data/factors/<project>/
    report.py generates result/: stratification, long and short, turnover, IC, IC decay, year-by-year
    result/                      results (summary.md is tracked; other files are generated)
data/                          local data, excluded from Git
  source/ downloaded original file, saved as is (CRSP, Compustat, CCM, FRED, Yahoo...)
  base/ Cleaned common data (crsp_monthly, compustat_quarterly, ccm_link, rf_monthly, french_factors_monthly)
  factors/ Factor data constructed by each project (exposure.parquet + meta.json)
```

## Workflow

```bash
# 1. Original data -> data/base (rerun is required only when data is updated)
python pipeline/build_crsp_monthly.py --start-year 2006 --end-year 2025 # About 35 minutes
python pipeline/build_compustat.py --start-year 2004 --end-year 2026
python pipeline/build_rf.py # French’s RF and factors

# 2. Build a factor -> data/factors/<item>/
python factors/jegadeesh_titman_1993_momentum/build.py

# 3. Generate results -> factors/<project>/result/
python factors/jegadeesh_titman_1993_momentum/report.py
```

## Conventions

- **Factor exposure**: One value per stock on each rebalancing date; higher values express a more bullish signal. Store exposures in long format `(date, asset_id, exposure)`, with CRSP PERMNO as `asset_id`.
- **No imports between factor projects**: Use `factorlab` and read shared data under `data/`. For another project’s factors, such as FF3 for risk adjustment, read `data/factors/<project>/`.
- **Data cleaning is only done once on `pipeline/`**: `build.py` does not read `data/source` directly.
- **The results are uniformly generated by `factorlab.report`**, and all projects use consistent metric definitions.
- **Long tables are used for storage and wide matrices are used for calculations**: `data/` contains long tables parquet, which are converted into date × asset matrix calculations when the framework reads them.
- **Timing**: Fix weights at the close of rebalancing date d and hold over (d, next rebalancing date]. IC relates the current signal to the following period’s return.
- **Sample period** unified in `factorlab.panels`: monthly rebalancing 2008-01 to 2025-11 (CRSP as of 2025-12), annual June formation 2008–2025.
- **Financial data are used according to the release date (point-in-time data)**: Each quarter has `available_date` = financial report release date `rdq`; if missing, use the end of the quarter + 90 days (about 10% of CRSP linkable quarters). The monthly financial factors only use the latest quarter published at that time at the end of each month (anything more than one year is considered expired); the annual June formation only uses the fiscal year published before June 30.
- **Financial factors exclude financial stocks**: Exclude based on the CRSP historical industry code SIC 6000–6999 of the current month (banks, insurance and other balance sheets are not comparable); price factors and FF3 retain financial stocks.
